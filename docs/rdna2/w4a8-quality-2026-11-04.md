# W4A8 MoE quality vs W4A16: Qwen3.8 Flash-Next TP4 (2026-11-04)

Question: how much does the production W4A8 MoE kernel
(`VLLM_RDNA2_W4A8_SDOT4=1` in `flashnext-mtp2`) cost in quality against
W4A16, with noise floors?

## Verdict

**W4A8 costs nothing measurable at task level and very little at token
level.** *Production view* (recipe as shipped, boot-to-boot floors; 2 x 128
teacher-forced 2048-token windows): W4A8 adds **+0.0019 nats/token of KL on
docs [95% CI +0.0018, +0.0022] and +0.0028 on mix [+0.0018, +0.0040]**. The
W4A16 floors are 0.0072 / 0.0095 and the W4A8 floors 0.0111 / 0.0134. It adds
+0.3 pt of top-1 disagreement over a 2.9-3.0 % floor. Perplexity does not
move: the NLL shift is +0.00004 [-0.0006, +0.0007] on docs and -0.0011
[-0.0046, +0.0029] on mix. On the 786-item task suite the pooled accuracy
shift is **-0.3 pt [-1.3, +0.8]**, flips over the floor are +0.4 pt [-0.3,
+1.1], and no family moves outside noise. *Kernel view* (fp32-accumulator
MoE epilogue, windows 0-31, within-boot floors): W4A8 adds **+0.0030 nats/token
[+0.0024, +0.0036] on docs and +0.0010 [-0.0005, +0.0023] on mix**, +0.5 /
+0.3 pt of top-1 disagreement, and an NLL shift of +0.0011 [-0.0008, +0.0029] /
+0.0071 [-0.0010, +0.0169]. That is the same size as the production view,
because the fp32 epilogue does not lower the floor. So W4A8's own error is a
small systematic shift (about 0.001-0.003 nats/token) plus 1.1-1.6x more
run-to-run noise than W4A16. Both sit far below what the tasks resolve.

**Separate finding: the server is not deterministic for identical
requests.** The same 2048-token window, scored twice in one boot, with both
passes cold and sequential, gives within-boot KL 0.010-0.016 nats/token and
top-1 agreement of 95-97 %. Only 0.0-0.6 % of positions return an identical
logprob. Single positions move by up to 15.5 nats within a boot and 16.8
nats between two W4A16 boots. This holds with
`VLLM_RDNA2_MOE_FP32_ACCUM=1` and without W4A8. The follow-up
([determinism-2026-11-04.md](determinism-2026-11-04.md)) traced it to the MoE
epilogue anyway: the fp32 epilogue also adds expert partials in arrival
order. The model then turns a single ULP in a single element into moves of
this size, through near-tied router top-k choices. It is not a correctness
bug. `VLLM_RDNA2_MOE_DETERMINISTIC=1` makes repeats bit-identical. The
original evidence is in
[Nondeterminism of identical requests](#nondeterminism-of-identical-requests).

All numbers are from tree `4a3db777ae` (`rdna_extras`,
`4a3db777aefa28e06036a355b20c4e0cd3edbcd9`) on HIP 2-5. Raw outputs and the
scripts are in `bench_results/2026-11-04_w4a8-quality/`.

## What W4A8 changes in this model

- The checkpoint quantizes only the routed experts. Its ignore list covers
  `lm_head`, the embeddings, MTP, PLE, vision, the router `.gate`, the
  hyper-connections, the indexer, linear and self attention, and the shared
  expert. The dense W4A8 path is never reached.
- `VLLM_RDNA2_W4A8_SDOT4=1` moves the routed-expert w13 and w2 GEMMs to the
  int8-activation sdot4 kernel (`moe_w4a8_gemm_rdna2`: v2 with
  `VLLM_RDNA_W4A8_KBLOCK=-1`, tile 8 from `VLLM_RDNA2_W4A8_BLOCK_M=8`). This
  happens only when the engine step carries at least 512 tokens
  (`W4A8_MOE_MIN_TOKENS` in `_rdna2_fused_moe`). Smaller steps (decode, MTP
  verify, short prefill chunks) stay W4A16. A step of 512 tokens or more runs
  W4A8 for every token in it, including decode tokens that share the step
  with a prefill chunk.
- In arm A the MoE GEMMs use the W4A16 kernel with tile 4. A 2048-token step
  stays below `VLLM_RDNA2_MOE_TILE8_MIN_TOKENS=4096`.
- The debug lines confirm the split: 0 W4A8 shape lines in A and A2, 1390
  (B) and 1400 (B2) lines with M from 513 to 20480 rows.

## Method

Each arm boots once and runs `scripts/hook.sh` as the `serve_validate.sh`
load hook (after the probe, PPL, prefix and warm-up checks):

1. **Teacher-forced windows** (`topk_kl.py collect`). There are 2 domains x
   128 windows x 2048 tokens (`windows.json`; token-id digest `fbac48de…`,
   file sha256 `b94341ac…`).
   - *docs*: technical Markdown (vLLM documentation, repository notes,
     benchmark tables) from `study_text_all.txt`, starting at token 800,000.
   - *mix*: OpenAssistant-style multilingual chat (`eval_mix.txt`, windows
     0-28), then `calib_mix.txt` (documentation, chat and code). Window 28
     straddles the two files.

   Each window is one sequential `/v1/completions` request: the token ids as
   the prompt, `prompt_logprobs=20`, `max_tokens=1`, temperature 0. A
   2048-token prompt is one 2048-token prefill step (`MAXBAT=2048`), so in
   the B arms the W4A8 kernel runs on every scored position. Requests with
   prompt logprobs do not read the prefix cache. vLLM accepted
   `prompt_logprobs` with MTP on, so no arm needed MTP turned off. For each
   of the 2047 scored positions per window the client keeps the actual
   token's logprob and rank and the top-20 ids and logprobs.
2. **Task suite** (`agentic_bench.py run`, which calls hi2 `bench/run.py`).
   Families: gsm8k, humaneval, mbpp, ifeval, toolcall, needle, decision,
   with `--limit 120` (decision has 66 items), 8 workers, seed 0, greedy
   (temperature 0) and thinking off. The Cline system prompt is
   `tools/agentic_bench/system_prompts/cline_act.md` from the
   `gfx1030_optimized` workspace repository (sha256 `31f13416…`, placeholders
   filled). It is prepended to every chat prompt, so every prompt is longer
   than 512 tokens (token table below). This is the production server: MTP2,
   prefix caching on, 8 concurrent requests.
3. **Teacher-forced gap on A's completions** (`agentic_bench.py tfkld
   score`, which calls hi2 `bench/tfkld.py`). Every arm scores arm A's
   completions, with prompt and completion sent as one prompt with
   `prompt_logprobs`. The gap is the token-weighted mean of
   `log p_A(t) - log p_X(t)`. A scores its own completions in its own boot,
   so the reference is the same pass type. These requests are 796 tokens or
   longer (A's prompt plus completion), so the B arms run them through W4A8.
4. **Within-boot repeat**: B, A2 and B2 score windows 0-15 of each domain a
   second time at the end of the boot (`topk_rep.npz`). This was added after
   arm A had finished.
5. **Kernel arms** Ad and Bd score windows 0-31 of each domain twice in one
   boot (`topk.npz`, then `topk_rep.npz`). They run no task suite.

Statistics (`scripts/summarize.py`):

- **KL**: a lower bound on KL(ref || cand), with no imputation. For each
  position, S is the union of the two top-20 lists' intersection and the
  scored token. Both logprobs are known for every token in S. Everything
  else goes into one tail bucket, and the KL of that coarse-grained
  distribution is taken. By the data-processing inequality this never
  exceeds the true KL. *Coverage* is the reference mass inside S. A unit
  test (`tests/tools/test_topk_kl.py`) checks the bound against the exact
  full-vocabulary KL.
- **top-1 agreement**: whether the two runs have the same argmax.
  **|dlogp|**: the absolute change in the logprob of the actual next token.
  **dNLL**: the change in mean NLL. **Identical positions**: positions where
  the server returned exactly the same logprob for the actual token.
- **Floors**: A-A2 (W4A16 boot to boot) and B-B2 (W4A8 boot to boot).
  **Cross pairs**: A-B, A-B2, A2-B and A2-B2. **Added by W4A8**: the mean
  over the cross pairs minus the mean over the floors. For small independent
  perturbations, KL adds: with per-run noise n_A, n_B and a systematic W4A8
  shift s, a floor is about 2 n_A or 2 n_B and a cross pair is about
  n_A + n_B + s, so the difference estimates s.
- **Intervals**: 95% bootstrap intervals over windows or items (10,000
  resamples for the added-effect tables, 2,000 for the per-pair repeat and
  kernel tables), resampled jointly for all four arms. Task pairs use hi2
  `bench/compare.py`: a paired bootstrap interval, the exact McNemar p and
  flip counts.

Evidence collected for the follow-up, which first treated this as a possible
correctness bug. The follow-up measured it in
[determinism-2026-11-04.md](determinism-2026-11-04.md): the routed-MoE
epilogue is the only run-dependent op (in both accumulation modes), and the
router's near-tied top-k choices amplify its ULP noise. That confirms the two
stages guessed in the last bullet.

- **Both passes are cold, full prefills.** Requests with `prompt_logprobs`
  skip the prefix-cache lookup: `skip_reading_prefix_cache` defaults to true
  when `prompt_logprobs` is set (`vllm/sampling_params.py:625-631`), and
  `KVCacheManager.prefix_cache_lookup_enabled` honors it
  (`vllm/v1/core/kv_cache_manager.py:251-253`). The counters agree. Across
  the topk, tfkld and repeat phases of every arm, prefix-cache queries stay
  at 31,720 and hits at 12,288 (both from the boot probes). In Bd's repeat,
  prompt tokens and computed prefill tokens both grow by exactly 131,072
  (64 windows x 2048; `vllm:request_prefill_kv_computed_tokens_sum`
  150,766 → 281,838). The per-snapshot counters are in `summary/summary.md`.
  Only Bd has an after-repeat snapshot, because it was added to `hook.sh`
  for that boot.
- **The scheduling is identical.** One request is in flight at a time, and
  each one runs as the same three steps: 1024 tokens, 1023 tokens, then the
  last token on its own (measured in the follow-up's trace; this list
  originally said one 2048-token step).
- **The moves have a shape.** Moves of 0.1 nat or more start at the first
  few positions of a window (median first position 0-5 in every arm and
  domain), when the context is only a few tokens long. The first move of 1
  nat or more comes at median position 7-46 in docs and 73-235 in mix
  (`first_move_*_by_window` in the JSON). In mix, the moves of 5 nats
  or more fall in a few windows (Ad: 26 in 6 of 32; Bd: 30 in 10 of 32) and
  late in the window: Ad's moves of 1 nat or more per 256-position bin are
  54, 20, 56, 86, 76, 90, 171, 246. Many of the largest mix moves are an
  `<|im_end|>` top-1 in one pass only. Examples: Bd mix window 28 position
  2009, `odal` at logp -0.16 (rank 1) vs -15.70 (rank 3899, top-1
  `<|im_end|>`); Bd mix window 26 position 1893, `_label` at -14.26 (top-1
  `<|im_end|>`) vs -0.31; Ad mix window 22 position 2034, `luxury` at
  -0.005 vs -10.0, after 82 earlier moves of 1 nat or more in that window.
  [INFERENCE] Two stages fit the data. First, a run-dependent difference
  shows up in rows that have almost no context, so something inside the
  2048-row step does not reduce in a fixed order (atomics, split
  reductions, or a row-mixing kernel). Second, a few windows amplify it into
  large, persistent moves (recurrent linear-attention state, or a discrete
  near-tie choice such as sparse-attention top-k or MoE routing).
- **The 50 worst positions per arm and domain** are in
  `summary/nondeterminism_positions.json`. Each entry has the window,
  position, token, logprob and rank for both passes, both top-1 tokens, the
  number and size of earlier moves of 1 nat or more in that window, the
  first such position, and the decoded context.
- **The 261-token PPL probe varies too.** It runs W4A16 in every arm because
  it is below the 512-token gate. It read 4.87, 4.82, 4.83, 4.82, 4.84 and
  4.87 on the six kept boots (A, B, A2, B2, Ad, Bd).

## Caveats

- **The KL is a lower bound** from the top-20 lists. Coverage is 0.973-0.975
  of the reference mass. Floors and cross pairs use the same estimator, so
  the added effect compares like with like, but absolute KL values are
  underestimates.
- **The floors are dominated by per-request nondeterminism.** The W4A8 effect
  is the difference of two noisy means, with joint-bootstrap intervals. The
  kernel view covers only windows 0-31 with one boot per arm, so its floor is
  within-boot and its cross pairs are cross-boot.
- **mix is not one source.** It is chat (`eval_mix.txt`, windows 0-28)
  followed by `calib_mix.txt` (windows 28-127), and window 28 straddles the
  two files. Its highest-KL windows for A-B are 28, 114, 22, 26 and 18 (KL
  0.044-0.087, against a mean of 0.0135).
- **W4A8 coverage in the suite.** W4A8 runs only in steps of 512 tokens or
  more: prompt prefill and any decode tokens that share those steps. Pure
  decode is W4A16 in both arms. So the task deltas measure W4A8 on prompt
  processing and the KV cache it writes, not on generation steps.
- **Task resolution.** There are 120 items per family (66 for decision). One
  flip is 0.8 pt (1.5 pt for decision), so per-family intervals are wide. The
  pooled interval (786 items) is about ±1 pt.
- **Gaps in coverage.** needle has no teacher-forced gap (hi2 `tfkld.py`
  scores chat tasks only). Arm A has no within-boot repeat, because the
  repeat was added after A finished. Every arm sets
  `VLLM_RDNA2_W4A8_MOE_DEBUG=1`, which only logs.
- **Bootstrap units.** The bootstrap resamples windows and items. Positions
  inside a window are correlated (moves persist along a window), so the
  per-position figures (top-1 agreement, |dlogp| quantiles) carry no
  position-level intervals.
- **No timing claims.** KFD evictions hit B and A2, so neither the logged
  phase durations nor the boot times are measurements.

## Reproduce

On the box, use the exact tree and stage the run directory
`W4Q=~/w4a8_runs/w4a8-quality-2026-11-04` as follows:

- `~/vllm-w4a8q-4a3d`: `git archive 4a3db777ae | tar -x`, a fresh `_rocm_C`
  build, and a `.sha` file.
- `$W4Q/tools/`: `topk_kl.py` and `agentic_bench.py` from
  `tools/rdna/port_v031/`.
- `$W4Q/hi2/`: `rdna-hint-flex-quantizer` at `3446cae`.
- `$W4Q/cline_act.md`, `$W4Q/text/`, and `$W4Q/scripts/` (this result
  directory's `scripts/`).

```bash
W4Q=~/w4a8_runs/w4a8-quality-2026-11-04 && cd "$W4Q"
PY=~/Apps/vllm/venv-7.14.0_0.32.0/bin/python
MODEL=~/.cache/huggingface/hub/models--wtdcode--Qwen3.8-Flash-Next-AWQ-W4A16/snapshots/0939125b929543a783ce700c90e36dd1a575c00c
# windows.json (sha256 b94341ac..., token-id digest fbac48de...); CPU only, no GPU
HIP_VISIBLE_DEVICES=-1 "$PY" tools/topk_kl.py windows --tokenizer "$MODEL" \
    --count 128 --seq-len 2048 \
    --domain "docs=$W4Q/text/study_text_all.txt@800000" \
    --domain "mix=$W4Q/text/eval_mix.txt@0,$W4Q/text/calib_mix.txt@0" \
    --out windows.json
setsid nohup bash scripts/run_arms.sh > run_arms.log 2>&1 < /dev/null &  # A B A2 B2
OWNER=W4A8Quality-fp32 ARMS="Ad Bd" bash scripts/run_arms.sh             # kernel arms
HIP_VISIBLE_DEVICES=-1 "$PY" scripts/summarize.py . results "$MODEL"
```

The `windows` command above regenerated a byte-identical `windows.json`.
`run_arms.sh` follows the HIP 2-5 lease, takes `BOOT_LOCK` for every boot,
and needs 28 GiB free on each card. Before each boot it removes a stale
`rdna_ar_wedged` marker. It retries a wedged arm from scratch, moving the
wedged boot's files to `arms/<arm>/attempt<k>/`. `tests/tools/test_topk_kl.py`
(CPU only) covers the KL bound against the exact KL, the pairing checks and
the system-prompt prefixing.
